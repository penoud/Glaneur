## Task

**US-EN-07 — Qt UI re-sourced in English.**

Seventh story of the sprint
`docs/sprints/2026-09-french-to-english-complete.md`.

Flip Qt's source language from French to English across every
`QCoreApplication.translate(...)` / `.tr(...)` call in the package.
The runtime French user experience is preserved by translating each
new English source back to its old French wording inside
``translations/glaneur_fr.ts``, then compiling the `.qm`.

### Rename table (context renames)

| Old context | New context |
|---|---|
| `Planificateur` | `Scheduler` |

Every other context is already English (`BugReport`, `Updater`,
`UiJournal`, `DialogueAPropos`, `DialoguePreferences`,
`MainWindow`, ...).

Note: the DialogueAPropos/DialogueSupprimees/DialoguePreferences
class names themselves remain French — a Python identifier rename
belongs to a later locals-cleanup US.

### `.ts` schema shift

- `translations/glaneur_fr.ts`: `sourcelanguage="en"`,
  `language="fr"`. Every `<source>` is now the new EN literal; every
  `<translation>` carries the old FR text so French users see the
  same UI.
- `translations/glaneur_en.ts`: `sourcelanguage="en"`, `language="en"`.
  Every `<source>` matches `<translation>` (or `<translation
  type="unfinished">` if translators want to review).

### Runtime behaviour

- French locale: Qt loads `glaneur_fr.qm`, resolves the English
  source strings to the populated French translations. User sees
  French.
- English locale: Qt loads `glaneur_en.qm` (or falls back to the
  source strings). User sees English.

## Directly modified

- `Glaneur/scheduler_labels.py` — every `translate("Planificateur", "…")`
  → `translate("Scheduler", "…")`, French source literal → English
  source literal. Local variables (`heures`, `secondes`, `minutes`,
  `jours`, `delai`, `prochaine`, `reste`) belong to a future locals
  cleanup and are NOT renamed here — they stay Python-side and the
  translation contract only depends on the argument literals.
- `Glaneur/bug_report.py` — every French source literal in the
  `BugReport` translate calls → English.
- `Glaneur/updater/qt_threads.py`, `Glaneur/updater/downloader.py`
  — every French source literal in the `Updater` translate calls →
  English.
- `Glaneur/engine/events.py` — docstring reference to
  ``QCoreApplication.translate("UiJournal", …)`` stays; the CLI
  ``_EN_TEMPLATES`` table is already English (US-EN-01/04).
- `app.py` — every `self.tr("…")` / `translate("…")` call.
  `DialogueSupprimees` `{fichier}` / `{date}` Qt placeholders are
  renamed to `{filename}` / `{date}` at the same time so the
  translation source strings are internally consistent (the Python
  dict keys `filename` / `deleted` were already renamed in US-EN-05).
- `translations/glaneur_fr.ts` — regenerated by `pyside6-lupdate`
  (or edited by hand), then every `<translation>` populated with the
  old French wording so the existing user experience is preserved.
- `translations/glaneur_en.ts` — regenerated; translations mirror
  source or stay unfinished.
- `translations/glaneur_fr.qm`, `translations/glaneur_en.qm` —
  rebuilt by `pyside6-lrelease`.

## Direct dependencies

- `Config`, `Options`, `Engine`, sources: unchanged.
- No manifest/cache/dispatch value touched.
- The `_render_ui` alias mentioned in the sprint doc turns out to
  live in ``app.py::_render_ui`` — a Qt-side mapper from EngineEvent
  code to translated text. Its templates flip from French sources to
  English sources at the same time.

## Explicitly out of scope

- **Class/attribute name renames** (`DialogueSupprimees`,
  `bouton_lancer`, `combo_classement`, `action_arreter_menu`, ...)
  — Python-side identifiers unrelated to Qt runtime translation.
  Belong to a locals-cleanup US.
- **CLI stdout summary FR text** (`téléchargées`, `reprises`,
  ...) — belongs to US-EN-08 residual mop-up.
- **AppStream metainfo files** — US-EN-08.
- **`__version__`** — unchanged.

## Tests

- `tests/test_scheduler.py::TestDisplayText` currently asserts on
  French substrings (`"désactivée"`, `"imminente"`, `" h "`,
  `" j "`, `"report"`). Those substrings are the runtime FR
  translations. Without a `QTranslator` installed in the test
  fixture, `translate` returns the source string, so tests must now
  assert on the English wording (`"disabled"`, `"imminent"`,
  `"h "`/`"h"` and `"day"`/`" d "`, `"deferred"`).
- No test currently pins the specific French wording of app.py
  strings.
- No new tests needed for Qt itself: the `.qm` files are generated
  artefacts and their correctness is asserted by manual smoke.
