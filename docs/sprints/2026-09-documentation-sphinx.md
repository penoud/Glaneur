# Sprint — Sphinx documentation and `docs/` cleanup

> **Archived on 2026-09-26.** Sprint finished — every user story
> US-01 to US-06 is ticked and the Definition of Done is reached
> (`sphinx-build -W -n` green, 137 / 137 public symbols documented,
> `docs/` restructured into `sphinx/` + `design/` + `sprints/`,
> `CLAUDE.md` updated).

Target version: patch (e.g. `1.1.1`). No runtime change.

## Goal

Give Glaneur an API documentation generated by Sphinx from the code,
unify the docstring format, and reorganise `docs/` by separating the
API doc (Sphinx), the living architecture notes, and the archived
sprints.

Decisions made at planning time:

- Docstrings in **Napoleon (Google-style)**, `sphinx.ext.napoleon`
  extension.
- Sphinx doc isolated in `docs/sphinx/`.
- `sprint-ci-workflows.md` archived in `docs/sprints/`.
- The old `todo.txt` (1.0.2 sprint) is archived in
  `docs/sprints/2026-09-preparation-publication.md`.

## Definition of Done

The sprint is ready when:

- `sphinx-build -W -n -b html docs/sphinx docs/sphinx/_build/html`
  produces HTML with no warning;
- every public function and class of `Glaneur/` carries a Napoleon
  docstring usable by autodoc;
- `todo.txt` reflects the next sprint (or is empty);
- `docs/` is structured into `sphinx/` + `design/` + `sprints/`;
- no test has been modified, no runtime change;
- `CLAUDE.md` references the concrete Sphinx path and the Napoleon
  style.
