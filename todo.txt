# Sprint — Documentation Sphinx et nettoyage `docs/`

Version cible : patch (ex. `1.1.1`). Aucun changement runtime.

## Objectif

Doter Glaneur d'une documentation API générée par Sphinx à partir du code,
uniformiser le format des docstrings, et réorganiser `docs/` en séparant la
doc API (Sphinx), les notes d'architecture vivantes et les sprints archivés.

Décisions actées au moment de la planification :

- Docstrings en **Napoleon (Google-style)**, extension `sphinx.ext.napoleon`.
- Doc Sphinx isolée dans `docs/sphinx/`.
- `sprint-ci-workflows.md` archivé dans `docs/sprints/`.
- L'ancien `todo.txt` (sprint 1.0.2) est archivé dans
  `docs/sprints/2026-09-preparation-publication.md`.

## US-01 — Inventaire des docstrings et choix confirmé du style

- [x] Lister les modules et symboles publics de `Glaneur/`, `app.py`,
      `cli.py`, `servette/`.
- [x] Classer chaque docstring : absent / prose libre / rST partiel.
- [x] Confirmer Napoleon (Google-style) et documenter le choix dans
      `docs/sphinx/README.md`.
- [x] Établir l'ordre de conversion pour US-03 en fonction du volume mesuré.

Résultat : 137 symboles publics, 65 avec docstring (47 %), 100 % en prose
libre. Aucune conversion rST à faire, uniquement de l'enrichissement
Napoleon. Détails et ordre de conversion dans `docs/sphinx/README.md`.

`servette/` sort du périmètre : ne contient que du `.pyc` (résidu du
rename), à traiter par un lot de nettoyage séparé.

Impact Map : lecture seule. Validation : aucune.

## US-03 — Conversion progressive des docstrings (Napoleon)

Un module = un commit, dans l'ordre :

- [ ] `Glaneur/engine.py`
- [ ] `Glaneur/sources/` (contrats d'adaptateur)
- [ ] `Glaneur/config.py`
- [ ] `Glaneur/scheduler.py`
- [ ] `Glaneur/systeme.py`
- [ ] `Glaneur/i18n.py`
- [ ] `Glaneur/logsetup.py`
- [ ] `Glaneur/bug_report.py`
- [ ] `Glaneur/updater/`
- [ ] `app.py`
- [ ] `cli.py`

Règles :

- Aucun changement de comportement, docstrings et commentaires uniquement.
- Après chaque module, `sphinx-build -W` reste vert.
- Ruff ciblé sur le fichier touché.
- Découper en deux PRs si le diff dépasse ~500 lignes.
- `invariant-reviewer` en fin de série pour confirmer la neutralité sémantique.

Impact Map par module : validation `local`.

## Ordre et parallélisation

1. **US-01** — bloque US-02 et US-03.
2. **US-02** ∥ **US-05** — indépendants, deux worktrees possibles.
3. **US-03** — séquentiel après US-02, module par module.
4. **US-06** — dernier, une fois la doc en place.

US-04 est en cours d'exécution : deux cases sont déjà cochées, il reste la
vérification `grep`.

## Definition of Done

Le sprint est prêt lorsque :

- `sphinx-build -W -n -b html docs/sphinx docs/sphinx/_build/html` produit
  un HTML sans warning ;
- toutes les fonctions et classes publiques de `Glaneur/` portent un
  docstring Napoleon exploitable par autodoc ;
- `todo.txt` reflète le prochain sprint (ou est vide) ;
- `docs/` est structuré en `sphinx/` + `design/` + `sprints/` ;
- aucun test n'a été modifié, aucun changement runtime ;
- `CLAUDE.md` référence le chemin Sphinx concret et le style Napoleon.

## Hors périmètre

- Refonte des invariants ou frontières documentés dans `CLAUDE.md`.
- Extraction de `sources/wordpress.py` (couvert par
  `docs/design/evolution-multi-sources.md`).
- Traduction anglaise des docstrings (écart connu #3 de `CLAUDE.md`).
- Publication de la doc sur ReadTheDocs ou GitHub Pages.
- Intégration de `sphinx-build` à la CI (à évaluer après US-02).
